# VM Compare South Africa

**The cheapest VPS and VM prices in South African data centres, compared and updated weekly.**

Live site: <https://vm-compare.fixes.co.za>

This is a fast, static comparison site and data pipeline. It tracks public VPS/VM pricing, normalises every price to VAT-inclusive South African rand, ignores promotional teasers, and ranks plans by the resources you actually get.

Companion to the [number1.co.za](https://number1.co.za) posts on [cheapest VPS hosting in South Africa](https://number1.co.za/cheapest-vps-linux-server-vm-in-south-africa/) and [best bang for buck VPS in 2026](https://number1.co.za/best-bang-for-buck-linux-vps-vm-in-south-africa-2026/).

---

## What it does

- Homepage with the cheapest plan at 1, 2, 4, 8, 16 and 32 GB, plus a full filterable table.
- Filters for minimum RAM, minimum vCPU, NVMe/SSD and provider, synced to the URL.
- Generated SEO landing pages such as `/cheapest-4gb-vps-south-africa/`.
- Provider pages with plans, features, reputation notes and a price-history chart.
- Separate international comparison for Johannesburg and Cape Town: Vultr, Akamai/Linode and AWS EC2.
- Weekly scraper that stores dated snapshots per provider and keeps last-known prices if a page breaks.
- Provider requests go through GitHub Discussions: <https://github.com/aral190/vm-compare/discussions>. No newsletter backend.

## Stack

- [Astro](https://astro.build) static output, hand-written CSS, one small vanilla JS filter island.
- TypeScript + Zod for the shared plan schema.
- `fetch` + `cheerio` for static pages; reader-proxy fallback for Cloudflare-protected pages.
- GitHub Actions for the weekly scrape and GitHub Pages deploy.
- Data lives in `data/` as reviewed JSON committed to git.

## Quick start

```bash
npm install
npm run dev          # http://localhost:4321
npm run build        # static output in dist/
npm run preview      # preview the production build
```

Useful checks:

```bash
npm run validate     # validate providers, plans and history
npm run check        # Astro + TypeScript diagnostics
npm test             # VAT normalisation tests
npm run scrape:dry   # scrape and print plans without writing
npm run scrape       # update plans.json, history and snapshots
```

`npm run seed` is only for bootstrapping the first dataset from `data/seed.json`. After that, `npm run scrape` is the source of truth.

## Data model

- `data/providers.json` — provider catalogue, URL, locations, VAT treatment, adapter and features. A provider may set `feedUrl` when prices come from a machine-readable endpoint separate from its public pricing page.
- `data/plans.json` — current normalised plans, generated by the scraper.
- `data/seed.json` — bootstrap plans and the manual fallback for archived providers.
- `data/history/<provider>.json` — dated price snapshots.
- `data/snapshots/<date>.json` — raw scrape results for debugging.
- `data/overrides.json` — manual corrections, matched by plan id.

Money is stored as integer rand cents. Every plan keeps both `priceInclVatCents` (the canonical comparison price) and `priceAsListedCents` (what the provider advertised).

### VAT rules

- `vat: "incl"` — keep the price.
- `vat: "excl"` — multiply by 1.15.
- `vat: "unknown"` — assume exclusive, multiply by 1.15, flag the plan with `vatAssumed`.
- The UI shows the as-listed price and a `*` on assumed rows.

### Scraper behaviour

- One adapter/parser per provider in `scripts/adapters/`.
- Promotions are ignored; recurring monthly prices are used.
- If a provider page fails, its plans are marked `stale` and the last-known price is kept.
- If every provider fails, `plans.json` is left untouched.
- Plans that disappear from a provider page are marked `stale`; archived plans stay archived.

## Outbound links

External provider and partner links get a single `utm_source` parameter:

```text
utm_source=vm-compare.fixes.co.za
```

The default is set in `src/lib/utm.ts` and can be changed with the `PUBLIC_UTM_SOURCE` environment variable (see `.env.example`) in `.env` or the build environment. Internal links and URLs that already have a `utm_source` are left unchanged.

## Adding a provider

1. Add the provider to `data/providers.json` with `adapter: "html"` (or `manual`).
2. Add a parser in `scripts/adapters/parsers.ts` and register it in `PARSERS`.
3. Run `npm run scrape:dry -- --provider=<slug>` and check the output.
4. Run `npm run scrape`, then `npm run validate`, `npm run check` and `npm test`.
5. Add the provider to the footer if it should appear in the short list.

If a site is JS-heavy or bot-protected, set `fetchMode: "jina"` (reader proxy) or implement the Playwright branch in `scripts/adapters/index.ts`. If the prices are rendered from a separate JSON endpoint, set `feedUrl` to that endpoint and keep `pricingUrl` as the public page linked from the site.

## Deployment

GitHub Pages, deployed by `.github/workflows/deploy.yml` on every push to `main`. The weekly update runs from `.github/workflows/update.yml` every Monday at 04:00 UTC (06:00 SAST).

### GitHub Pages settings

- Source: **GitHub Actions**
- Custom domain: `vm-compare.fixes.co.za`
- Enforce HTTPS: on after the certificate is issued

## Methodology

The full methodology is on the live site at <https://vm-compare.fixes.co.za/methodology/>:

- VAT is normalised to 15% inclusive.
- First-month and limited-time promotions are ignored.
- Ranking is by absolute monthly price by default, with price per GB RAM as a value view.
- Qualitative factors (NVMe, backups, support, location) are shown as badges and notes rather than hidden in an opaque score.
